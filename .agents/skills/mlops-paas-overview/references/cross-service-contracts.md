# Cross-service contracts

- **Identity** — Keep tenant, Project, version, Build, Deployment, Workspace, Training Job and Drift Run UUIDs distinct. Operator labels, environment and API routes must identify the same resource. Use the actual dispatch adapter and recipient to confirm required fields.
- **Object ownership** — Storage paths are assembled under `services/control-plane/src/infrastructure/storage/` and the owning domain service. For Training, [workspace and job contracts](../../mlops-paas-backend/references/training-workspaces.md) identifies where to check drafts, immutable job objects and legacy paths. Project assignment preserves job storage/runtime identity.
- **Images** — Trace packaging inputs, Harbor or Docker tags, registration and deployment through `apps/deployment` and the selected backend. Verify promotion rules in [CD](../../../../.github/workflows/cd.yml) and the consuming manifests.
- **Callbacks and recovery** — [Service contracts](../../mlops-paas-backend/references/service-contracts.md) covers authorization, retry and terminal state. Check the actual handler and producer together before changing an auth header, body or state transition.
- **Telemetry** — Start at the [Model Server](../../mlops-paas-backend/references/model-server.md) and [Consumer](../../mlops-paas-backend/references/consumer.md) references. Confirm the topic, payload and database fields on both sides of ingestion.
